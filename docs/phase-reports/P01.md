## Source requirements and decisions addressed

- **R01 / R13 / BO §7–8:** Backend modular monolith scaffold; on-prem/LAN-oriented local PostgreSQL workflow (`docker-compose.yml`, `.env.example`).
- **PROPOSED stack** per ADR 0001: Node 24, Express 4, TypeScript strict, Prisma 6.8, Zod, Pino, Helmet, Vitest/Supertest.
- No auth, business CRUD, or business schema migrations (P02 gate).
- No invented financial/RBAC policies.

## Architecture implemented

- `apps/api/src/modules/health/` — routes → controller → service → repository.
- `apps/api/src/shared/` — env (Zod), errors, HTTP helpers, logging, Prisma client, transaction helper, middleware.
- `apps/api/src/app.ts` — Express pipeline: request ID, Helmet, optional CORS (explicit origin only), Pino HTTP, JSON limit, `/api/v1` router, 404 + error handler.
- Root `docker-compose.yml` — PostgreSQL **16.8-alpine**, host port **5433** (avoids local 5432 conflicts), named volume.
- Integration tests use **embedded-postgres** on port **55432** when `ITDMS_TEST_DATABASE_URL` is unset.

2. **Port 5432 conflict** — host mapped to **5433** in compose and `.env.example`.
3. **Integration DB** — embedded PostgreSQL + `createDatabase('itdms_dev')`; shared single `beforeAll` for tests.
4. **npm allow-scripts** — Prisma client generation run via `npx prisma generate` when postinstall blocked.
